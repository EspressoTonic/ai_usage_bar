# Architecture

One app process owns provider requests, system sampling, the session inventory and a versioned local bridge. SwiftUI displays cached state; opening a menu does not synchronously fetch providers or parse transcripts. Provider refreshes run independently and coalesce. Credentials stay in their adapter. Optional Antigravity reports and named Codex sources use bounded short-lived native subprocesses; no browser engine or persistent quota worker is embedded.

`ProviderClient → AppStore snapshot → native menu / Unix bridge → CLI → optional BTT widget`

System CPU is tick-delta utilization; memory used is active+wired+compressed pages, labeled accordingly. Memory pressure is an OS event signal. System sampling is every 2 seconds while a dashboard is visible, 10 seconds in the background and 30 seconds under Low Power. Turning it off performs no Mach sampling.

Session scanning examines at most 256 candidate filenames per day across seven recent directories and parses at most 32 files. Per file, read a 16 KiB head and 128 KiB tail; unchanged files reuse the cached model. Lifetime token usage is ignored. A reading's timestamp is retained, and missing values remain unknown. No prompts are retained in models/caches. Metadata observation never grants native compaction capability.

The chat-control Codex RPC adapter uses a user-selected existing loopback WebSocket endpoint. It never spawns a replacement chat-owning server or resumes an existing thread for monitoring. Main-actor operation gating serializes transport work. Native compaction checks the current loaded/idle status and the selected chat ID again. The response acknowledgement is not completion; a matching `contextCompaction` item-completed event is required.

Bridge requests are newline-delimited JSON v1. Each message is bounded; socket directory/file permissions are private; peer UID must match. The server owns its socket and rejects a second running collector. Same-user processes may use the bridge by design; it is not a security boundary against malicious software running as that user. Allowed actions are status, capabilities, refresh, select and compact. Default bridge views redact account fingerprints and omit chats; external select/compact require an in-app permission that resets each launch. At most four asynchronous handlers are in flight. No shell/credential export action exists.

The BTT preset captures the rendered chat target and selection revision. Its action consumes a private captured request valid for 30 seconds; a selection race is rejected. Physical BTT rendering/click timing still requires verification. The core and add-on have separate packaging paths; only the generic bridge client is included with the app.

Preferences and quota-only cache use CryptoKit AES-GCM and an app-specific Keychain key. Disk and Keychain work run in a storage actor. Chat inventories, selections, operations and system history are excluded from the cache model. Migration encrypts reduced models before removing old plaintext files, and failures preserve old data without a plaintext fallback. Read [SECURITY.md](../SECURITY.md) before adding credentials, diagnostics, exports or new bridge actions.

Provider credential reads validate the opened descriptor and reject special files, leaf symlinks, foreign ownership, broad POSIX file permissions and oversized/growing input. Provider HTTP uses a streamed 1 MiB body collection limit, declared-length preflight, no error-body retention and explicit task cancellation. Retry delays are finite and bounded. These checks do not alter provider-owned files or require their parent directory to be private.

## Quota detail sources

Named Codex profiles are additive optional preferences, disabled on creation and bounded to eight. A single main-actor queue serializes their probes and generations discard cancelled/removed results. The separate native stdio exchange sends initialize/initialized, account/read without forced token refresh, account/rateLimits/read, account/read, then terminates. It does not use the chat-control client or grant compaction capabilities. A before/after reported-account comparison rejects identity changes. Account IDs are hashed with the source binding; missing IDs are not a stable identity claim. Prefer rateLimitsByLimitId over the legacy single bucket, and keep each reported window/credit pool separate.

CommandProbe shares bounded output, monotonic deadlines, cancellation and process-group cleanup between report commands and a response-driven JSONL dialogue. Stdio writes are nonblocking, protected against SIGPIPE and capped; no raw native diagnostics are displayed. The local executable is resolved/validated and launched directly in a private directory with a limited environment. SSH uses a strict alias and POSIX-quoted absolute paths with BatchMode, existing host trust and no forwarding/local commands/multiplexing; no arbitrary shell-command field exists. SSH/native behavior after disconnect needs remote live validation.

Optional quota history is a separate AES-GCM file with source/account/window/reset-scoped points and seven-day/1,000-point bounds. Unchanged polls do not rewrite it; the collector expires points even when no source succeeds. Antigravity and unverified native identities do not enter history/alerts. The notification transition machine only observes fresh successful readings, uses silent initial baselines and deduplicates low events per cycle. Settings explicitly requests OS notification permission. Neither history nor named profile data is exposed by the bridge, even with external chat access enabled.

Menu percentages reuse the selected cached source/window and become unavailable after ten minutes or a reported reset/error. Pace requires an explicit duration, a plausible future reset and at least 3% elapsed; it uses captured usage, not lifetime tokens. Dashboard charts use the current reset window and system Swift Charts. No third-party package or Touch Bar dependency was added.
